# Bug sweep and security audit, 2026-10-20

Scope: all of `src/` (about 6,000 lines outside the simulator). Threat model: ReTweak runs elevated (PawnIO, fan control),
next to files and settings that the unelevated user, or anything running as the user, can change. The
question for each elevated path is whether user-level code can use it to gain administrator rights, read or
write files only administrators can, or make the fans unsafe.

## Fixed in this sweep

| # | Area | Severity | Problem | Fix |
|---|------|----------|---------|-----|
| 1 | Security: diagnostics bundle | Medium | "Save diagnostics" (elevated) copied `*.csv` from `LogFolder` in the user-editable `settings.json`, and `settings.json` from `%LocalAppData%\ReTweak`, without the profile-folder and junction checks used elsewhere. User-level code could point either at a folder only administrators can read and have the files copied into a zip on the user's Desktop. | Only copied from plain folders in the user's profile (`TrustedPaths.IsAllowedUserFolder`); only `retweak-*.csv`; links skipped. |
| 2 | Safety: settings load | Medium | `settings.json` was used without validation, although the Settings dialog validates. A damaged or tampered file could set failsafes to 1000 °C, an empty curve (every tick throws) or nonsense targets, and the elevated app would drive the fans from it. | `AppSettings.Load` runs the same validation; a failing section falls back to its defaults and the reason is logged. |
| 3 | Bug: fan control error | Medium | If a fan-control tick threw, the app showed the error but left the fans at the last manual speed, with no failsafe running. | The fans are handed back to the driver (`FanController.ReleaseToDriver`) and the error is logged. |
| 4 | Bug: NaN power | Medium | An unreadable or 0 W power limit gives a NaN power fraction. It stuck in Auto's look-ahead and integral permanently and could be saved into `airflow.json`, so every later session started poisoned. | Non-finite power counts as moderate load and doesn't drive learning; non-finite saved airflow entries load as 0. |
| 5 | Bug: one failed write stops control | Low | A single failed fan write (e.g. a driver reset after a TDR or update) left ReTweak off for the rest of the session in every mode, including the failsafes. | Retried after 30 s, unless the error is about permissions, which won't fix itself. |
| 6 | Bug: exit race | Low | `FanController` was disposed from ProcessExit/UnhandledException on other threads while the UI timer ticked. A tick in the middle of a write could set the fans again just after they'd been handed back. | Ticks, option changes and Dispose are serialised with a lock. |

Earlier today, separately: Start with Windows broke because of hardening added in #9 (fixed in #12).

Tests: six new simulator scenarios ("Failure handling"). Full build: 0 warnings. `--simulate`: all pass.

## Checked and fine

- **PawnIO**: loads only the embedded signed NVIDIA module; calls two read-only functions with fixed-size buffers; output length checked.
- **I2C (ASUS Power Detector)**: read-only, only probed on ASUS boards (subsystem vendor 0x1043), bus access serialised.
- **Window messages**: the tray window lets lower-integrity processes send only "show" (`ChangeWindowMessageFilterEx`); "exit" can't come from an unelevated process.
- **Logon task**: per-user, the user's SID only, highest privileges, exe by full path, task XML protected while schtasks reads it, registered task verified afterwards.
- **Process launches**: schtasks and explorer by full system path, no ShellExecute; links https only.
- **Elevated writes**: diagnostics in an admin-only `%ProgramData%` folder; settings and airflow use atomic, link-refusing writes; the connector log is limited to plain folders in the profile.
- **Foreground app**: name only, local only, used for activity detection.

## Remaining risks (not fixed)

1. **The exe runs elevated from a user-writable folder** (Medium). The startup task launches `bin\Debug\...\ReTweak.exe` under Documents. Anything running as the user can replace it and get administrator rights at the next logon. The app's own security check warns about this. Fix: install to `C:\Program Files\ReTweak` (proposed as its own task).
2. **Junction race on user-folder writes** (Low). `WriteFileSafely` checks the folder for links, then writes. A process racing it could swap in a junction between the check and the write, getting the elevated app to drop `settings.json` or `airflow.json` (ReTweak's JSON, fixed names) in another folder. Closing it fully means writing by handle (NtCreateFile relative to a verified directory handle), or moving the elevated copy's writes to an admin-only folder.
3. **Hard kill leaves a manual fan speed** (Low). If ReTweak is killed (Task Manager, a native crash), the fans stay at the last manual speed until the driver resets. The GPU's own thermal protection still applies. A small watchdog service could hand them back.
4. **GPU Tweak III's IOMap driver** is installed and flagged by the security check (an older vulnerable driver). Not ReTweak's, but uninstalling it if GPU Tweak III isn't needed removes the risk.
